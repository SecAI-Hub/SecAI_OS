Your data stays on this device

SecAI OS is designed to run inference locally on your hardware. GPU acceleration is used when a supported, verified runtime is active; otherwise supported workloads may use a CPU fallback. In the offline_private profile, appliance policy blocks intended service egress by default. Always check the live status below.

What's running right now

Your appliance is running in the offline_private profile.

  • Network: blocked — no data leaves this device
  • Vault: encrypted with AES-256 (LUKS2 + Argon2id)
  • Models: verified through a 7-stage quarantine pipeline before use
  • Services: each service has a documented mix of systemd, seccomp, namespace, and filesystem controls; Landlock applies only where the capability matrix says it does
  • Audit: supported control-plane events use hash-chained logs; coverage and checkpoint verification are shown on the Security dashboard

What happens if something goes wrong

  • Tampered model detected: promotion is blocked and the artifact remains contained for review; removal depends on the configured response policy
  • Integrity check fails: configured containment controls are requested and the result is recorded; confirm enforcement in the live status
  • Suspicious activity: configured agent-freeze, airlock-containment, and vault-relock brokers attempt enforcement and report failures
  • Bad update: rollback is available only when Greenboot and a verified previous deployment are present and healthy
  • Worst case: 3-level emergency panic — lock, wipe keys, or full wipe

No telemetry

SecAI OS does not collect any telemetry. No usage analytics, no crash reports, no phone-home, no heartbeat. The only network activity is what you explicitly enable by switching to the "research" or "full lab" profile. Search is designed to use Tor and mediation; other allowlisted full-lab egress may use the airlock without Tor. PII filtering reduces exposure but cannot guarantee that all identifying content is removed.

How to verify

You don't have to take our word for it:

  • The Security dashboard shows real-time verification status
  • Audit logs are hash-chained — any tampering breaks the chain visibly
  • Release signatures and provenance are security evidence only when the installed artifact includes them and verification succeeds
  • Model promotion requires the enabled quarantine gates to succeed; consult the scan report for skipped or unavailable gates
  • Export a forensic bundle for independent verification

For the full technical security model, see the Security dashboard.
